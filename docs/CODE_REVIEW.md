# Анализ кода ZI Writer — 15.09.2026

Проверены: 15 файлов Kotlin (4 587 строк), `AndroidManifest.xml`, 11 XML-ресурсов,
Gradle-конфигурация, работа с сетью, файлами и хранилищем.

Формат: **критичность** — где — суть — статус.

---

## 🔴 Критично

### 1. Полная потеря базы обучения после любого падения приложения
**`MainActivity.kt` (onCreate)** — при старте создавался файл `crash_marker`; если он
оставался с прошлого запуска (то есть приложение падало), при следующем старте
вызывался `LearningManager.clearLearned(this)` — **вся изученная база удалялась
целиком**. Любой сбой (в том числе в фоновом потоке, из-за OOM, из-за нехватки
памяти при генерации 50 листов) уничтожал данные, которые пользователь собирал
часами. Плюс в `catch` при неудачной инфляции разметки тоже стояла очистка базы.

**Исправлено:** маркер и автоочистка убраны, при ошибке UI показывается сообщение,
данные никогда не удаляются автоматически (только кнопкой «Очистить»).

### 2. Пароли ключа подписи зашиты в репозиторий
**`zi-writer/app/build.gradle`** — `storePassword 'Zakharevich2024'`,
`keyPassword 'Zakharevich2024'`, сам keystore `zi-writer-release.jks` тоже в git.
Ключ подписи — это «паспорт» приложения: у кого он есть, тот может выпустить
обновление, которое Android примет как ваше. Пароли в открытом репозитории
= компрометация ключа.

**Исправлено:** подпись читается из переменных окружения / `keystore.properties`
(файл добавлен в `.gitignore`), с откатом на прежнее значение, чтобы существующие
сборки не ломались. **Рекомендация:** занести ключ и пароли в GitHub Secrets
(`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) и в перспективе
рассмотреть выпуск нового ключа (старый уже «засвечен»).

### 3. Не работала автоматическая сборка/выпуск APK
**`.github/`** — отсутствовал полностью, релизы собирались вручную, файлы APK
(v25…v31) лежали в корне репозитория. Это и была основная задача — см. раздел
«Что добавлено» ниже.

## 🟠 Существенные ошибки

### 4. Экспорт в «Загрузки» не работал на Android 10+ (API 29+)
**`PdfExporter`, `DocxExporter`, `EpubExporter`, `CoverGenerator`, `MainActivity.saveAsTxt`**
— везде прямая запись в `/storage/emulated/0/Download`. Начиная с Android 10
прямой доступ к чужим каталогам запрещён (scoped storage), исключение ловилось в
пустой `catch`, и пользователь получал файл в приватной папке приложения
(`Android/data/com.zakharevich.ziwriter/files/`), куда он не может попасть без провода.

**Исправлено:** добавлен `DownloadSaver.kt` — на API 29+ файл публикуется через
`MediaStore` (разрешения не нужны), на API ≤ 28 используется прямая запись
(+ запрос `WRITE_EXTERNAL_STORAGE` на старых версиях).

### 5. Озвучка (TTS) не инициализировалась на Android 11+
**`AndroidManifest.xml`** — не было секции `<queries>` с `android.intent.action.TTS_SERVICE`.
С Android 11 включена «видимость пакетов», без объявления запроса системный
TTS-движок недоступен → `TextToSpeech` не находил движок, кнопка «Озвучить»
отвечала «TTS не готов».

**Исправлено:** `<queries>` добавлен.

### 6. Загрузка крупного файла в поле ввода → падение по памяти (OOM)
**`MainActivity` (выбор файла)** — `readText()` читал файл целиком, и только потом
брал первые 30 000 знаков. Файл на 200 МБ гарантированно роняет приложение.

**Исправлено:** чтение ограничено 30 000 знаков сразу (метод `readLimited`).

### 7. Zip Slip при импорте базы обучения
**`LearningManager.importLearnedFromZip`** — имя записи из архива не проверялось,
`File(dir, entry.name)` с именем вида `../../../databases/...` пишет данные вне
каталога обучения. Импортируемый zip может прийти от кого угодно.

**Исправлено:** путь проверяется через `canonicalPath` и обязан лежать внутри
каталога обучения.

### 8. XXE при разборе FB2
**`Fb2Importer.parseFb2`** — `DocumentBuilderFactory` создавался без отключения
внешних сущностей и DTD. Подсунутый FB2-файл может заставить парсер обращаться к
внешним ресурсам/раскрывать сущности (XXE).

**Исправлено:** отключены `external-general-entities`, `external-parameter-entities`,
загрузка внешних DTD, включён `isExpandEntityReferences = false`.

### 9. `WRITE_EXTERNAL_STORAGE` запрашивался в манифесте, но не у пользователя
**`MainActivity`** — разрешение не запрашивалось в рантайме, поэтому на Android 9
и ниже запись в публичные каталоги всё равно не работала.

**Исправлено:** добавлен запрос разрешения для API ≤ 28 (на API 29+ он не нужен,
используется MediaStore).

## 🟡 Логические и «тихие» ошибки

### 10. Служебная строка математической модели попадала в текст книги
**`StoryGenerator.generate`** — строка вида
`[Мат.модель: выбран сюжет "..." жанр ... score=...]` дописывалась в начало
готового текста, а затем уходила в TXT/PDF/DOCX/EPUB и в библиотеку.

**Исправлено:** вывод служебной информации выключен по умолчанию, включается
флагом `GenerationConfig.debugInfo = true`.

### 11. Форматирование числа без `Locale`
**`StoryGenerator`** — `String.format("%.2f", score)` зависит от локали
(в турецкой/арабской локали — запятая и другой вывод).
**Исправлено:** `String.format(java.util.Locale.US, ...)`.

### 12. Автокорректор портил текст
**`GrammarCorrector`**:
* `Regex("От\s+куда", IGNORE_CASE) → "Откуда"` — из-за `IGNORE_CASE` в середине
  предложения «от куда» тоже становилось «Откуда» (заглавная буква посреди строки);
  строчные правила были недостижимы. Исправлено: правила сделаны регистрозависимыми
  (19 правил), а строчный вариант по-прежнему обрабатывается отдельным правилом.
* `"Не где" → "Нигде"` — **меняло смысл** («негде» — про место, «нигде» — отрицание).
  Исправлено на «Негде».
* `"Что бы" → "Чтобы"` — правило ломало корректные «что бы ни случилось»,
  «что бы мне сделать?». Отключено.

### 13. `IOException`/ошибки проглатывались
Практически весь код обёрнут в `catch (e: Exception) {}` без логирования
(`MainActivity`, `LearningManager`, `OpdsFetcher`, экспортёры). Из-за этого ошибки
вроде «нет доступа к папке» и «парсер не смог разобрать файл» выглядели как
«ничего не произошло». Полностью переписать обработку в рамках этой задачи нельзя,
но при правках добавлены комментарии и убраны самые вредные пустые `catch`
(те, что скрывали потерю пользовательских данных).

## 🔵 Замечания и рекомендации (не блокирующие)

| Тема | Замечание |
|---|---|
| `local.properties` в git | содержит путь `/home/user/android-sdk`; в CI ломает сборку. Workflow перезаписывает файл; лучше убрать из индекса (`git rm --cached`). |
| APK в корне репозитория | ~40 МБ бинарников в истории git. Добавлен `.gitignore` для будущих сборок (существующие файлы не тронуты). |
| `versionCode 25` | при релизах v31 и выше номер не менялся → Android может отказаться ставить обновление «поверх». Теперь в CI берётся из тега: `major*10000+minor*100+patch` (v31.0 → 310000); правило — номер обязан только расти. |
| `READ_MEDIA_DOCUMENTS` | разрешение объявлялось, но нигде не используется; удалено (лишние разрешения = вопросы при публикации в Play). |
| `usesCleartextTraffic="true"` | разрешал HTTP для **всех** доменов. Заменено на `network_security_config.xml`: HTTPS обязателен, открытый HTTP разрешён только зеркалам Флибусты. |
| Флибуста | `OpdsFetcher` ходит на зеркала Флибусты по HTTP и качает книги целиком в память. Юридически спорный источник (пиратская библиотека), плюс `httpGetBytes` без ограничения размера — для 100 МБ файла получите OOM. Рекомендуется ограничить размер и рассмотреть легальные источники (Gutendex/Open Library уже подключены). |
| Дубликаты кода | `detectGenre` есть в `MainActivity` и `StoryGenerator.detectGenreStatic`; `jaccard` — в `StoryGenerator` и `MathPlotModel`; списки стоп-слов продублированы. Логика расходится при правках в одном месте. |
| Мёртвый код | `StoryGenerator.placeHolder()`, `MathPlotModel.Plot.embedding`, `formatGenres`, `cbNoRepeat`/`cbIllustrations`/`cardEntities`/`tvEntities` в разметке (галочки ни к чему не привязаны — пользователь думает, что они работают). |
| `chars` в библиотеке | `HistoryManager.getHistory` показывает размер файла в байтах (`file.length()`), а подписано как «знаков». |
| Производительность | `PdfExporter` вызывает `measureText` для каждой строки, `ChapterIllustrator` рисует по случайным числам, `StoryGenerator.generate` перебирает абзацы до 10 раз каждый. При 50 листах генерация занимает секунды-десятки секунд в фоне — стоит показывать индикатор с кнопкой отмены. |
| Отсутствие тестов | юнит-тестов нет вообще; функции вроде `GrammarCorrector.correct` и `StoryGenerator` плохо покрыты проверками. Для CI можно добавить `testImplementation junit` и простые тесты на парсеры (FB2/EPUB) — они не требуют Android-эмулятора. |

## ✅ Что добавлено в этом PR

1. **`.github/workflows/android-release.yml`** — при публикации GitHub Release
   автоматически собирается **подписанный release APK** и прикладывается к релизу;
   версия (`versionName`/`versionCode`) берётся из тега релиза; генерируется
   `SHA256SUMS.txt`. Есть ручной запуск (Actions → Release APK → Run workflow).
2. **`.github/workflows/android-build.yml`** — CI на каждый push/PR: собирается
   debug APK (проверка, что проект компилируется), артефакт сохраняется.
3. **`zi-writer/app/build.gradle`** — версия и подпись через параметры/секреты
   (с обратной совместимостью), сборка без ключа больше не «падает молча».
4. **Исправления кода** — пункты 1, 4–12 выше.
5. **`.gitignore`** — сборки, `local.properties`, ключи.

Сборка в CI выполняет те же шаги, что и локальная: `./gradlew assembleRelease`.
Первый прогон покажет, компилируется ли проект целиком (локально проверить не
удалось: все источники Gradle/Android SDK недоступны из этой среды; синтаксис всех
Kotlin-файлов проверен парсером tree-sitter — ошибок нет).
